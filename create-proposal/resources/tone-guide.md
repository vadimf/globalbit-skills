# Tone & Style Guide — Winning Proposals

## Voice Characteristics

| Trait | Description |
|-------|------------|
| **Authoritative** | Speak from a position of expertise. You've done this before, successfully. |
| **Concise** | Every sentence earns its place. No filler, no padding. |
| **Persuasive** | Lead the reader to the inevitable conclusion: Globalbit is the right choice. |
| **Benefit-driven** | Features are secondary. Outcomes are primary. |
| **Results-focused** | Quantify wherever possible. Numbers build trust. |

## Weak Phrases — NEVER USE

| ❌ Don't Say | ✅ Say Instead |
|-------------|---------------|
| "We hope to..." | "We will..." |
| "We think this might..." | "Based on our analysis, this will..." |
| "We'll try to..." | "We commit to..." |
| "This could potentially..." | "This delivers..." |
| "If things go well..." | "Upon completion..." |
| "We believe..." | "Our experience confirms..." |
| "Hopefully..." | (Remove entirely) |
| "We suggest considering..." | "We recommend..." |
| "It's possible that..." | "This achieves..." |
| "Sprint Planning / Daily Standups / Sprint Retrospectives" | "2-week sprints with a live demo at the end of each sprint" |
| "Definition of Done" | (Remove entirely — internal concept only) |
| "UTM Parameters" | "the channel the visitor arrived from" / "ערוץ שממנו הגיע המבקר" |
| "Agile methodology" | (Don't name the methodology — describe the process) |
| "State-of-the-art" or "cutting-edge" | Use specific capabilities instead |

## Technical → Business Outcome Translation

Always reframe technical work as business impact:

| ❌ Technical Statement | ✅ Business Outcome |
|----------------------|-------------------|
| "We will build an AI model using TensorFlow" | "We will deploy a predictive AI engine that reduces processing time by 35%" |
| "We will set up CI/CD pipelines" | "Automated deployment pipeline that reduces release cycles from weeks to days" |
| "We will implement automated testing" | "An automation framework that eliminates 80% of manual testing effort" |
| "We will use React Native for the mobile app" | "A fully functional cross-platform mobile application serving both iOS and Android from a single codebase" |
| "We will optimize SQL queries" | "Database optimizations that improve page load times by up to 60%" |
| "We will implement role-based access control" | "A security framework that protects sensitive operations and enforces separation of duties" |
| "We will use Docker and Kubernetes" | "Container-based infrastructure ensuring 99.9% uptime and horizontal scalability" |

## Deliverable Language

Make every deliverable tangible and specific:

| ❌ Vague | ✅ Specific |
|---------|-----------|
| "Documentation" | "A comprehensive functional specification document with user flows, wireframes, and technical requirements" |
| "Testing" | "A regression test suite covering 52 critical user journeys across 8 device configurations" |
| "Mobile app" | "A fully functional Flutter-based mobile application with offline support, push notifications, and real-time data sync" |
| "Dashboard" | "A real-time executive dashboard reducing reporting effort by 50% with automated KPI tracking" |
| "Website" | "A responsive, SEO-optimized web platform with <2s load time and AA accessibility compliance" |

## Section-by-Section Writing Notes

### Executive Summary

- Maximum 1 page
- Paragraphs (2-3) + takeaway bullets (3-4) + vision close
- **NO TABLE** — budget/timeline as inline text, hours never mentioned
- Written for the **Decision Maker** — strategic, ROI-focused
- End with a vision/confidence sentence, not numbers

### Background & Context

- Show understanding of the client's business and industry
- Reference specific challenges they face (from meetings, RFPs, research)
- Position the project within their strategic goals
- 3 paragraphs max — personas/use-cases belong in the discovery phase

### Proposed Solution

- Open with **"Our Approach" / "הגישה שלנו"** — strategic framing first
- Components as **narrative paragraphs**, not What/Why/Deliverable bullets
- Every component ends with **"The business impact:"** — one sentence
- Use Revenue Engine / Growth Platform vocabulary
- Include QA as a component (4-layer approach)

### Risk Management

- Present proactively — risk management is a STRENGTH, not a liability
- Use severity × probability matrix (1-5 scale)
- Every risk must have a mitigation plan
- Include Israel-specific risks (security situations, remote work readiness)

### Commercial Section

- Lead with the model (T&M / Fixed / Retainer)
- Present hourly rates in a clean table
- Include payment terms (Net +5 standard)
- Add assumptions and boundaries clearly
- Never present rates apologetically — they reflect premium quality

### Call to Action (Close)

Always end with a strong, specific next step:

- **EN**: "We propose scheduling a strategic alignment session next week to finalize scope and initiate the Discovery phase."
- **HE**: "אנו מציעים לתאם פגישת יישור אסטרטגית בשבוע הקרוב לצורך אישור סופי של התכולה והתחלת שלב הדיסקברי."

## Hebrew-Specific Notes

- Use formal but warm Hebrew (not overly stiff)
- Technical terms can stay in English (API, CI/CD, Docker, Sprint, etc.)
- Client names and product names stay in their original language
- Numbers and currencies: use ₪ or ש״ח / ש"ח
- Dates: DD/MM/YYYY format
- The word "גלובלביט" (not "Globalbit") in Hebrew proposals, though "Globalbit" in headings is acceptable
