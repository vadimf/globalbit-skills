# Service Playbook: Specification & Discovery

> **When to use**: Client needs requirements gathering, functional specification, UX research, or discovery phase before development.
> **Reference proposals**: Payment Slip (Proposal 1), Macabi Pharm (Proposal 7)

---

## Overview

Specification & Discovery is typically the **first engagement** with a client. It produces the foundational documents that guide all subsequent development. Position this as a **strategic investment** — not overhead.

### Key Selling Points

- Reduces development risk by 60–70% by catching misalignment early
- Creates a shared understanding between business and technical stakeholders
- Globalbit's **Zetra AI** tool reduces specification time by ~70%, freeing human experts for strategic thinking
- Deliverables become the baseline for development budgeting and planning

---

## Typical Phases

### Phase 1: Research & Analysis

- Stakeholder interviews (identify pain points, objectives, constraints)
- Existing system audit (if applicable)
- User research (interviews, surveys, usage data analysis)
- Competitive benchmarking (2–5 competitors)
- Deliverable: **Requirements Document** + **Research Findings Report**

### Phase 2: UX Concept

- Information Architecture (sitemap, navigation hierarchy)
- User Flows for critical paths
- Customer Journey Maps
- Initial wireframes (low fidelity)
- Client sync and approval
- Deliverable: **UX Concept Document** + **Sitemap** + **User Flows**

### Phase 3: Detailed UX Specification

- Screen-by-screen specification
- Interaction patterns and edge cases
- Responsive behavior (mobile, tablet, desktop)
- Error states and empty states
- Deliverable: **Detailed UX Spec** (per screen/module)

### Phase 4: UI Concept

- Visual design language (colors, typography, button styles, component library)
- 2–3 design alternatives for key screens
- Accessibility standards (AA compliance)
- Client approval on visual direction
- Deliverable: **UI Concept Document** + **Mockups**

### Phase 5: Interactive Prototype

- Clickable prototype (Figma or equivalent)
- All critical user flows implemented
- Mobile + desktop versions
- Internal testing + client feedback
- Deliverable: **Interactive Prototype** (Figma link)

### Phase 6: Final Documentation

- Developer handoff guide (component specs, spacing, interactions)
- User guide (if applicable)
- Technical documentation
- Deliverable: **Dev Handoff Package** + **Style Guide / UI Kit**

> **Hebrew version from real proposals:**
>
> 1. המטרה היא לייצר לכם יתרון תחרותי, לא רק לספק מסמכי אפיון
> 2. נחשוב כמו יזמים. לא רק נפתח, נחפש גם הזדמנויות עסקיות
> 3. נשים דגש על פיתוח המותאם לצמיחה עתידית ועמידה בעומסים
> 4. נייצר חוויית משתמש המבוססת על עקרונות פסיכולוגיים מוכרים
> 5. נעצב ממשק נגיש בהתאם לתקנות ישראל

### English equivalents

1. The goal is to create competitive advantage, not just deliver specification documents
2. We think like entrepreneurs — beyond building, we identify business opportunities
3. We design for future growth and scalability from day one
4. User experience grounded in proven psychological principles
5. Accessible interface design complying with Israeli accessibility regulations

## Risks Specific to This Service

| Risk | Severity | Probability | Mitigation |
|------|:-:|:-:|-----------|
| Scope creep during research phase | 4 | 3 | Define clear research boundaries upfront; time-box interviews |
| Stakeholder disagreement on priorities | 3 | 3 | Facilitate structured prioritization workshops; document decisions |
| Incomplete access to existing systems | 3 | 3 | Request access in kickoff; define alternative research methods |
| Changing business requirements mid-spec | 4 | 2 | Change control process; version document with approval gates |
| Low user research participation | 3 | 2 | Define participant criteria early; provide incentives if needed |

## Value Framing

Position specification work as:

- **Insurance against expensive development mistakes** — "Catching a requirement gap in specification costs 10x less than fixing it in development"
- **Budget clarity** — "A proper specification is the foundation for accurate development estimation"
- **Stakeholder alignment** — "Everyone sees the same picture before a single line of code is written"
- **Strategic competitive edge** — Not just fulfilling requirements, but identifying business opportunities through the specification process
