# Service Playbook: UI/UX Design

> **When to use**: Client needs user experience research, interface design, prototyping, or visual design as a standalone engagement (not embedded in a development project).
> **Reference proposals**: Macabi Pharm (Proposal 7)

---

## Overview

UI/UX Design engagements deliver the **blueprint** for exceptional digital experiences. Position this as a **competitive differentiator** — great UX is the difference between products users tolerate and products users love.

### Key Selling Points

- Award-winning design team (multiple App Store "App of the Year" awards)
- Research-driven: every design decision backed by user data
- Zetra AI reduces specification documentation time by ~70%
- Full lifecycle: research → concept → detailed design → prototype → developer handoff
- Accessibility-first: AA compliance built in from the start

## Typical Phase Structure

### Phase 1: Research & Analysis (2–3 weeks)

- Stakeholder interviews (business goals, constraints, vision)
- User research (interviews, surveys, usage analytics)
- Current system UX audit (if applicable)
- Competitive benchmarking (3–5 competitors)
- UX workshop with client team
- **Deliverables**: Requirements document, research findings report, benchmark analysis

### Phase 2: UX Concept (2 weeks)

- Information Architecture (sitemap, navigation hierarchy)
- User flows for critical paths
- Customer journey maps
- Initial wireframes (low fidelity)
- Client sync and concept approval
- **Deliverables**: UX concept document, sitemap, user flows, journey maps

### Phase 3: Detailed UX Specification (3–5 weeks)

- Screen-by-screen specification
- Interaction patterns for all states (default, hover, active, error, empty, loading)
- Responsive behavior specifications (mobile, tablet, desktop)
- Content strategy per screen
- Flowcharts for complex processes
- **Deliverables**: Detailed UX spec (per screen/module), flowcharts

### Phase 4: UI Concept (1–2 weeks)

- Visual design language definition (colors, typography, button styles, spacing)
- 2–3 design alternatives for key screens
- Brand alignment review
- Accessibility standards compliance (AA)
- Client approval on visual direction
- **Deliverables**: UI concept document, mockups (2–3 alternatives)

### Phase 5: Interactive Prototype (2–3 weeks)

- Clickable prototype for all critical flows
- Micro-interactions and basic animations
- Mobile + desktop versions
- Internal usability testing
- Client feedback and iterations
- **Deliverables**: Interactive prototype (Figma link)

### Phase 6: Detailed UI Design (3–5 weeks)

- Complete visual design for all screens
- Desktop + mobile responsive designs
- UI Kit / component library
- Style guide (colors, typography, spacing, icons)
- Accessibility verification
- **Deliverables**: Final screen designs, UI Kit, style guide

### Phase 7: Developer Handoff (1–2 weeks)

- Developer handoff guide (component specs, interactions, spacing)
- QA coordination
- User guide (if applicable)
- Technical documentation
- **Deliverables**: Dev handoff package, documentation

### Phase 8: Implementation Support (Ongoing)

- Clarifications for development team
- Design adjustments for technical constraints
- QA review against design specs
- Visual regression review
- **Deliverables**: Ongoing support (billable on T&M)

## Risks Specific to This Service

| Risk | Severity | Probability | Mitigation |
|------|:-:|:-:|-----------|
| Excessive revision cycles on visual design | 3 | 4 | Limit to 2 revision rounds per phase; decision gates |
| Stakeholder disagreement on design direction | 3 | 3 | Early concept presentations; RACI matrix for approvals |
| Research phase revealing unexpected complexity | 3 | 3 | Time-box research; focus on MVP flows first |
| Design not technically feasible | 3 | 2 | Developer review at concept phase; ongoing tech sync |
| Accessibility requirements adding scope | 3 | 3 | AA compliance included by default; AAA scoped separately |
